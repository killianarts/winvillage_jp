Around a week ago, I finished adding the sales ledger feature to the
Winvillage software.

Here is how I implemented it.

1. I made a model called Transaction to hold data for any kind of
   transaction.
2. I made a view to access Transaction objects.
    - The view has a few key features.
        1. After getting a sorted QuerySet of Transactions, get some
           values from an HTMX request, or if there is no HTMX request, I
           set default values.
        2. Using those values, I then filter the QuerySet further. This
           lets me view an arbitrary set of transactions.
        3. To create the 'balance' column of the ledger, since the balance
           is the result of the interaction of two different transactions,
           it didn't make sense to create a model or model field to store
           the value. That's especially true since I want the ability to
           view the balance at any arbitrary window of time.
        4. Instead, in the view, I start the balance at zero, add/subtract
           the price of a transaction to/from the balance, and then pack
           the transaction and the 'current' balance into a nested list.
        5. I add the transaction/balance list, along with the 'final'
           balance into the context
        6. I then unpack the transaction/balance list in the template
           and present them on the same table row. I present the final
           balance computed in the view on the last row.
    - The result is that I only have "virtual" ledgers.

At first, I thought that urls could look something like
"transactions/2023/9/10", but it wasn't possible because filtering
using form data requires validation **after** accessing the url, but
the url needs to be the result of the submitted form data. Chicken/egg
situation. Instead, using HTMX, I just have http get query values that
I grab in the view and use for the filtering action.
